## 基于现有项目的未来价值

现有基础是 100 款中文目录、99 个已核实 Steam 对应链接、100 条玩法概述和静态生成器。未来 SEO 价值来自**可检索的中文整理、持续可比的数据快照与有口径的类型参照**。仅重复来源清单并加长文案，搜索增量有限。若后续出现有独立结论的类型页或游戏追踪页，才值得增加可索引页面；不需要机械拆成 100 个薄详情页。

未来有正式公开网址后，可为稳定页面配置精确标题与摘要、canonical、分享预览图，并确保页面允许索引。当前页面的 `noindex` 和未部署状态只说明今天没有搜索入口；这些是未来上线时的条件，不是此刻要做完的 SEO 任务。来源应在页面说明中透明列出，但站点名称采用独立表述，例如“从 Game Jam 到 Steam｜游戏数据观察”。

维护价值取决于是否形成一套可重复的“小快照”：保留静态单页与 Python 生成方式，新增快照元数据，统一生成日期、状态计数和校验；以人工复核少量歧义为主。当前 `collect.py` 只补新游戏，不会更新已有 Steam 状态；现有 `build.py` 和 `validate.py` 中有写死的 70/29/1 数字，未来需要从快照计算。项目不必变成实时平台，若停止跟踪，可固定最终快照和方法说明，继续作为可引用资料。

如添加“Steam 好评数”，需同时保存评测总数、语言、购买来源和采集时间；好评数不是销量。类型改为多标签后，一款游戏分别进入各类型参照组，并显示每组样本量、中位数与该游戏位置。先明确参照范围是“这 100 款”还是更大的 Steam 游戏样本，否则“同类型水准”会误导读者。Steam 官方旧评测接口已标记弃用，实施采集前需依据当时的官方接口文档复核。
